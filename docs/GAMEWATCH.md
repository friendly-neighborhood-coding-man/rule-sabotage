# GameWatch: Kane-powered game QA, blind fault-injection demonstration

Status: **READY_FOR_HACKATHON_SUBMISSION**. The experiment is complete: results, test counts and limitations are in [`GW1_FINAL_REPORT.md`](GW1_FINAL_REPORT.md). Built on PR #20 (`7d2f34f`).

GameWatch is a small, portable QA harness: it takes evidence from a game's **existing** playtests (scripted runs, AI
self-play, human sessions), presents it as an anonymous evidence site, has Kane review it blind, and hands the findings
to a coding agent that must reproduce, fix and re-verify them. Rule Sabotage V6.1 is the demonstration game. Nothing new
was simulated: every record comes from the game's own engine, referee and opponents.

> This document describes the experiment and is for the operator. It is excluded from the coding agent's blind
> workspace. Kane never sees the repository; it sees only the evidence site.

## SkillBook architecture (2026-11-24 update)

GameWatch is a SkillBook (`gamewatch/skillbook/book.json`, 14 tasks in three groups: Collector, Porter, Analyzer)
executed by **SkillFlow**, a separate, domain-independent runner (own repo
https://github.com/friendly-neighborhood-coding-man/skillflow, MIT, with its own example and 9 self-tests).
GameWatch vendors SkillFlow's `runner.py` and `LICENSE` unmodified at pinned commit `da9785a`
(`gamewatch/vendor/skillflow/VENDOR.json`: URL, commit, license, sha256; `python gamewatch/vendor/verify.py`). No
submodule, no runtime download. Both were written on 2026-11-24 by the same author with Claude Code; SkillFlow first, then
vendored. See `gamewatch/README.md` for prerequisites and commands.

**End-to-end check from a standalone checkout** (fresh `git clone` of this branch, no install):
`verify.py` OK, then the book ran discover → collect (kept the frozen bundle) → gaps (all 15 rules exercised on both
builds) → pages (regenerated byte-identical) → leak check (56 pages clean) → Kane plan (frozen inputs OK) → balance, and
**stopped at the Kane review with `needs-authorization`** (exit 2) in about 1 s. With a SkillFlow authorization but the
code gate still disabled, resuming the run made `gamewatch/kane/run.ts --execute` refuse before any Kane process, and the
book stopped (exit 3): Kane needs both. In a second fresh clone with the bundle deleted, the book collected everything again (22 cases,
32 games, about 3 minutes): the new bundle is **identical to the frozen one except for wall-clock fields** (generation
time, per-game milliseconds), so the evidence is reproducible. The book then stopped at the Kane plan because the fresh
bundle is not the frozen one, as designed: Kane may only review frozen inputs.

Operator procedure for the one Kane call: the manual script `gw1-manual-run.ps1`, kept **outside the repository**
(project files, as with KS1), so filling in its approval fields cannot touch the tree it checks. It refuses while its
approval fields are PENDING; checks HEAD and that the gate, runner, server, book, vendored runner, evidence and site are
unmodified (tracked files only); runs the free part of the book if no run exists; requires the SkillFlow checkpoint to be
`needs-authorization` at exactly `analyze-kane-review` and no `coding-agent` authorization (file or environment); writes
the single-use approval, enables the gate for that process only, creates the `kane-paid` authorization and resumes the
book once (the Kane task calls kane-cli exactly once; a second call for the run id is refused), and restores the gate and
clears the token in `finally`. The book then stops at `analyze-fix` (coding-agent authorization), or ends with the report
if Kane produced no valid finding. Rehearsed end to end in a scratch clone with a **fake** kane-cli (test double, no
credits): one ledger call, one finding stored with a valid nonce, counted by the coverage audit, stop at `analyze-fix`.

The freeze was refreshed once before any Kane call (only `gamewatch/run-evidence.ts` changed: an option to keep an
existing bundle, and the build list moved into `gamewatch/private/`); evidence and site hashes are unchanged; the
history is recorded in `FREEZE.json`.

GameWatch's own balance step (`steps/balance.ts`, engine statistics, not Kane) already shows the first-mover action
surplus in QX-73 (actions minus pieces: +1.0 per first-mover turn, 0 elsewhere). Its output is not shown to Kane.

## Playable variants and isolation

The normal playable game (`server/v6/`, `npm run play:v6`) is **unchanged**. `gamewatch/builds.ts` materializes builds as
git-ignored copies `server/v6-build-<label>/` (siblings of `server/v6/`, so imports resolve unchanged) and applies a
build's source changes as exact text replacements that must match once. Each change is separately switchable.

| Build | Contents | Shown to Kane as |
|---|---|---|
| `QX-41` | clean V6.1 (byte-identical copy) | "Build QX-41" |
| `QX-73` | three planted changes (private manifest) | "Build QX-73" |
| `gt-clean`, `gt-B1`, `gt-B2`, `gt-B3` | one change each | never (private tests only) |

Both evidence builds are fully playable through the same code paths (`aiTurnV6`, `refereeV6`, `applyMove`, `endTurn`).

## Ground truth (frozen before any Kane call)

Private: `gamewatch/private/` (`mutations.json` = exact source changes and intended violations, `GROUND_TRUTH.md`,
`probes.ts`, `groundtruth.test.ts`, `score.ts`, `FREEZE.json` = sha256 of the manifest, tests, tools, scenarios, bundle
and every site page). `npm run gamewatch:groundtruth`: **8/8 pass**: the clean build shows none of the defects, each
single-mutation build shows exactly its own, controls match clean everywhere, and the clean build equals the playable
engine byte for byte.

**The referee does not hide the planted defects** (checked): all three appear in real play with the unchanged referee.
An earlier candidate (an owner-dependent freeze duration) would have been caught by the referee's own symmetry check
E2, so it was not used.

## Evidence produced (real runs, `evidence/gamewatch/`)

* 11 scripted playtests × 2 builds = **22 cases**; all 32 scripted placements went through the real referee: 30 engine-approved on
  both builds alike, and the 2 placements next to a piece refused on both builds, as rule R5 requires.
* **32 AI-vs-AI games**: seeds 97001–97008 × first mover swapped × 2 builds, `softmax-v2` in both seats (about 6–36 s
  per game).
* Site: 56 static pages (`evidence/gamewatch/site/`): rules R1–R15, playtest source, builds, case pages with state
  before/after and engine events for every step, match pages per turn, aggregate balance indicators, findings form.
  Checked for leaks: no labels, manifest ids, expected verdicts or defect counts.

## Proposed Kane evaluation (as prepared before GW1)

`npm run gamewatch:kane-plan` prints it and verifies the frozen inputs. One **objective-mode** call
(`kane-cli run "<objective>" --url http://127.0.0.1:3210/index.html --agent --headless --max-steps 80 --timeout 2700`)
over the loopback site; Kane submits up to 6 findings through the report form, each with a category (confirmed
observable anomaly / suspected bug needing reproduction / balance hypothesis / clean), cited case/match ids, a
reproduction and a suggested fix. The objective is neutral: it names the kinds of problems to look for (rule
violations, inconsistency, life-cycle, balance) as the brief asked, never which, where or how many.

* Why not analyzer mode: it only answers fixed boolean conditions; writing conditions that can catch these defects
  would reveal them. Analyzer mode cannot generate unrestricted bug reports and this plan does not claim it can.
* Budget (GW1 update): **80 steps, `--timeout 2700` s, process killed at 2730 s**, so Kane can open far more of the 56
  pages. No credit ceiling is a constraint: kane-cli 0.10.4 has no credit limit anyway. The gate still needs a ceiling
  field; it is set to 300 for bookkeeping only (worst-case estimate 80 × 3.1 = 248 never binds), which makes the gate
  require a balance of at least 450 before the call. Credits (balance before/after) and elapsed time are logged in
  `ledger.ndjson` and `run/GW1-blind-review/meta.json`. One call, no retry, explicit approval and the single-run gate
  unchanged. The one earlier objective call (KX1) cost 40.09 credits.
* Risk: Kane may still not open every page and may report only what the index aggregates show. That is measured, not
  hidden. All findings are kept, including partial ones and failed runs.
* The report page matches its path in an OS-independent way (`gamewatch/kane/serve.ts` `resolvePage`, tested for posix
  and Windows paths in `serve.test.ts` with a test-double submission that reaches the coverage audit).

## Closed loop: one repair attempt (done; results in GW1_FINAL_REPORT.md)

Authorized by the operator on 2026-11-24 19:06 UTC: one coding-agent repair attempt through the SkillBook, no further
paid Kane calls. Operator script `gw1-repair-run.ps1` (outside the repository). Design:

* **Blind input only:** the workspace (`export-workspace.ts`) is the committed tree without history, with the build under
  test as `server/v6/engine.ts`, the documented rules, and Kane's valid findings verbatim (all three). Removed: private
  ground truth, this document, the Kane plan and runner, the SkillBook, the evidence bundle and site (they name the other
  build), the gameplay-freeze hashes and test (they identify the clean engine), the submission banner, and npm scripts
  that point at removed files. Checked by exporting a workspace and searching it: no manifest, defect names, build
  labels, clean-engine hash or experiment description remain, and the existing V6 tests pass on the build under test, so
  they reveal nothing either. The agent's CLI runs headless in the workspace with web tools off and shell use limited to
  the commands the brief needs. Limitation: a permitted `node` command could still read files outside the workspace.
* **One attempt:** `steps/fix.ts` records `evidence/gamewatch/repair/attempt.json` before the agent starts and refuses a
  second attempt, so the regression review's loop back to the fix step goes to the report instead. Neither the
  reference comparison nor the ground truth can guide another attempt.
* **Agent brief:** reproduce each finding before changing the game code, minimal fixes, regression tests that fail
  before and pass after, re-run of the same scripted playtests and matched games, `CLOSED_LOOP_REPORT.md`.
* **Freeze:** when the agent exits (or is stopped at 3300 s, before the task's own timeout), every file it changed or
  added is copied to `evidence/gamewatch/repair/output/` and hashed in `repair/FREEZE.json`. The book then re-runs the
  playtests freshly on the corrected code and compares them with the reference build.
* **Independent evaluation, after the freeze only:** `gamewatch/private/evaluate-repair.ts` verifies the freeze,
  materializes every changed game file and runs the frozen probes against the clean baseline (each planted defect fixed
  or still present; controls unchanged or regression), runs the agent's tests and the V6 tests, and, with the manual
  labels of Kane's findings, reports detected, missed, repaired and remaining defects separately.
* Rehearsed end to end in a scratch clone with a stand-in agent (a test double, labelled as such, not a real repair):
  export, one attempt, freeze, refusal of a second attempt, fresh re-run, regression review, report, evaluation.

## Closed loop (original preparation)

1. Operator: `node --experimental-strip-types gamewatch/closed-loop/export-workspace.ts QX-73 <dir> notes.ndjson`.
   The workspace is a history-free copy in which `server/v6/engine.ts` is the build under test and `gamewatch/private/`,
   this document and the evidence bundle are removed. The agent must also be run without network/repository access.
2. Coding agent: follows `gamewatch/closed-loop/AGENT_BRIEF.md` (reproduce each finding with a scripted playtest, fix,
   re-run the same scripts and matched games, write `CLOSED_LOOP_REPORT.md`).
3. Operator: `node --experimental-strip-types gamewatch/private/score.ts <agent's engine.ts> notes.ndjson` re-runs the
   frozen probes on the corrected engine (B1/B2/B3 fixed or still present, controls unchanged or regression) and prints
   Kane's findings next to the ground truth for manual labelling: true detection, missed, false positive, unsupported.
   (Checked on the unfixed build: all three "still present"; on the clean engine: all "fixed", controls unchanged.)
