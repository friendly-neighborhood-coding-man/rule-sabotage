# Claude handoff — Rule Sabotage V2 (Korean operator prompt)

## Paste into Claude

Rule Sabotage V2를 이어서 개발해줘. 제공된 ZIP이 유일한 코드 베이스라인이야. 기존 ProofLoop, 보안 데이터셋, 기타 프로젝트에는 손대지 마. 목표는 KaneCLI 온라인 해커톤에서 *재미있고 실제 플레이 가능한* 인간 vs AI 게임의 V2를 완성하고, Kane CLI의 **실제 검증 루프**를 증명하는 것이야.

### 반드시 유지할 규칙

1. 7×7 턴제 격자판, 인간 vs OpenRouter 상대 AI. 매 라운드 가로/세로/대각선/3×3 중 공통 도형 하나만 랜덤으로 정해지며 양측이 같은 도형을 봐야 한다.
2. 각자 N개의 규칙 슬롯을 갖고 추가/교체/제거 가능. 자연어로 작성한 효과를 해당 도형의 유효 칸에 배치한다. 소유자와 무관하게 *그 칸을 밟은 누구에게나* 적용된다. 밟은 개별 칸은 1회 발동 직후 소멸한다.
3. OpenRouter는 (A) 인간·AI 자연어를 제한된 DSL로 해석하는 **Compiler**와 (B) 게임에 최선을 다해 임하는 **Opponent** 두 역할. 상대 AI는 현재 라운드에 인간이 제출한 비공개 행동을 절대로 볼 수 없다.
4. Kane CLI는 (C) **공정성 독립 검증자**. Kane CLI는 현재 일반적인 저지연 게임 API가 아니라 브라우저 검사 도구이므로 매턴 호출을 기본 전제로 놓지 마. 실제 지원되는 호출 방식을 확인하고 공정성 오류를 찾고 수정 전후 증거를 남겨. 게임의 최종 판정은 결정론적 엔진. Kane이 심판인 척하는 문구는 실제 Kane 검증 결과가 없으면 쓰지 마.
5. LLM으로부터 실행 가능 TypeScript/JavaScript를 받지 마. TypeScript에 정의된 유한한 JSON DSL과 명령 실행기만 허용. 현재 효과 back/freeze/forward/shield는 최소 샘플이야. 확장이 필요하면 먼저 타입·파서·공정성 경계·테스트를 작성해.
6. 공정성: 양측 동일 기계적 규칙, 영구/다중 턴 속박·승리 조작·특정 사용자만 표적·실세계 작업 전부 금지. 3×3+freeze는 현재 impact 18 > 14로 차단. 이 수치는 초기 가설이며 실험으로 조정할 수 있어.
7. Kane이 검증했거나 OpenRouter가 실제로 돌아갔다고 허위 보고하지 마. API 키·로그인·Kane 설치 부재는 명확히 BLOCKED/NOT_RUN으로 구분. 테스트 통과와 실제 제품 완성도를 혼동하지 마.

### 첫 작업 (순서 필수)

A. ZIP 해제 후 `npm test`, `npm start`. README, `docs/ACCEPTANCE.md`, `docs/KANE_AUDIT.md`를 먼저 읽고 앱 기능을 재현. Node 22+로 실행. `server`와 `client`의 코드가 서로 비슷한 이유를 파악하고 중복된 엔진 구현을 하나의 공유 패키지로 정리하되 비결정적 회귀가 없도록 해.

B. 모델을 연결할 수 있으면 사용자가 제공한 API 키를 환경 변수에만 저장하고, OpenRouter 공식 docs/무료 모델 목록에서 `structured_outputs`와 현재 무료 정책을 확인하고 실제 호출. 한국어 20, 영어 10, 거부 10, AI 전략 10 사례를 새로 봉인한 테스트셋으로 독립 측정. API 사용 한도와 반복 호출을 측정. 모델이 JSON을 준다고 믿지 말고 입력·출력 모두 검증.

C. 실제 Kane CLI가 있는 환경에서 `docs/KANE_AUDIT.md`의 검사 K01–K11을 실행. 진짜 Kane 증거만 기록. **Kane 검출 문제 → 수정 → 동일 조건 재실행**을 시도해. 발견할 문제가 없으면 조작하지 말고 그 사실 그대로 보고.

D. 현재는 브라우저가 게임 상태를 소유한다. 배포 전에 세션·게임상태·턴 결정·결과를 서버 권위로 옮기고, 인간 행동 제출 후 AI 호출에도 그 행동을 공개하지 않도록 보호. API 키는 절대 HTML/클라이언트 번들에 넣지 마. 요청/응답에 실제 개인정보를 포함하지 마.

E. 플레이 테스트로 재미를 다듬어. 두 플레이어 모두 이동만 하는 것보다 함정을 사용하는 편이 의미 있게 설계되었는지 관찰하고, 10매치 이상 지표를 남겨. 전략을 일부러 약하게 만들어 웃긴 결과를 연출하지 말 것. 감각적으로는 가볍고 블랙코미디 같은 UI가 좋지만 원작 게임의 캐릭터/이미지/맵을 모방하지 마.

### 제약과 종료

- 기존 V1 정규 기능을 최대한 유지하고, 큰 리라이트를 하지 마. 범위 밖 인프라/결제/실제 이메일 연결 금지.
- `.env`, 인증 정보, 사용자 개인 데이터는 커밋하지 마.
- 테스트 결과, 모델 호출 수/비용, Kane 버전/증거 경로, 알려진 한계, 사용자가 직접 실행할 절차를 `docs/evidence/V2_STATUS.md`에 정리해.
- 사용자 승인 없이 public 배포, git push, PR merge, 금전적 결제 금지.
- 로컬 검증을 마치면 `READY_FOR_OPERATOR_V2_REVIEW`에서 중단하고, 실제 PASS/BLOCKED 항목을 따로 보고해.

### 현재 코드 범위

- `client/engine.js`, `client/ui.js`, `client/guard.js`, `client/adapters.js`
- `server/contracts.ts`, `server/openrouter.ts`, `server/server.ts`, `server/engine.cjs`, `server/guard.cjs`
- `tests/` 와 `docs/`의 사양 및 검증 계획

최우선 성공 기준은 **'사람이 한국어 한 문장으로 함정을 만들고, 실제 AI가 최선을 다해 경쟁하며, 양쪽의 규칙을 같은 기준으로 심사하는 한 판이 끝까지 돌아간다'**는 것이야.
