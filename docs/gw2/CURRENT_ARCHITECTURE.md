# Current architecture (GW1 as submitted) and what GW2 does with it

Inspected at `d22d33eeed06370559fe016a2647965875fce42b` (`claude/project-thread-1a20hc`, PR #21) and
`46ee7e6b3717eeff682f14a4fae10612f7a5f902` (`followup/gw1-visit-coverage`) on 2026-11-25. Every claim below points at
a file. "Reuse" means use unchanged, "extend" means add to it in a later phase (reference tier), "untouched" means
frozen (see [`COMMON_SPEC.md`](COMMON_SPEC.md) §1).

## 1. Data flow today

```
server/v6/engine.ts (clean, frozen)
   │  gamewatch/builds.ts materializes server/v6-build-<label>/ (git-ignored) from a change list
   │  (private change list: gamewatch/private/evidence-builds.ts, mutations.json)
   ▼
gamewatch/adapters/rule-sabotage.ts  +  gamewatch/scenarios.ts (11 scripts)  +  AI self-play (16 matched games/build)
   │  gamewatch/run-evidence.ts all
   ▼
evidence/gamewatch/evidence.json   (gamewatch/evidence@1: game.rules R1–R15, builds, 22 cases, 32 matches)
   │  gamewatch/dashboard.ts                                │ skillbook steps: gaps.ts, balance.ts
   ▼                                                        ▼
evidence/gamewatch/site/ (56 static pages)           evidence/gamewatch/qa/*.json
   │  gamewatch/kane/serve.ts (loopback; POST /report → notes.ndjson with nonce)
   ▼
Kane (objective mode, one call, gamewatch/kane/run.ts --execute, gated)
   │  stdout.ndjson (Kane's own step log), notes.ndjson (forms), ledger.ndjson (balance)
   ▼
audit.ts (citation coverage) → fix.ts (one coding-agent attempt, blind workspace, freeze) → regression.ts → report.ts
   ▼
gamewatch/private/evaluate-repair.ts (operator only, after the freeze) + labels.json (manual, after the freeze)
```

The whole chain is the SkillBook `gamewatch/skillbook/book.json` (14 tasks) run by the vendored SkillFlow runner
`gamewatch/vendor/skillflow/runner.py` (commit `da9785a`).

## 3. Existing patterns GW2 should reuse instead of reinventing

* **Freeze by LF-normalised SHA-256 manifest**: `gamewatch/private/FREEZE.json`, `evidence/gamewatch/repair/FREEZE.json`,
  `VENDOR.json`. GW2 hypothesis freezes, partition manifests and the baseline manifest use the same convention.
* **Append-only, hash-chained journal**: the balance loop already has one (test "the journal is append-only and
  hash-chained: edits are detected and further appends refused", `tests/balance.test.ts`). The judgment graph (P2)
  should follow that implementation's conventions; Phase 0 did not read it in detail.
* **Pre-registration before results**: `tests/balance-v2.test.ts` ("contracts are registered before results exist,
  immutable, and evaluation refuses results that predate registration") and the sealed holdout ("the final holdout is
  sealed until corrections are frozen and never leaks into exploration pages"). These are direct precedents for P3/P5.
* **Provenance labels**: "only a stored real kane-cli output can be labelled Kane; the test double never can"
  (`tests/balance-v3.test.ts`). GW2 author labels in the judgment graph follow the same rule.
* **Closed value sets with strict validation**: rule text → effect mapping in `server/rules.ts` refuses anything
  outside a closed set ("effect values are a closed set", "model replies are validated strictly", `tests/rules.test.ts`). The hypothesis
  representation (P4) follows this style.

## 4. Gaps between GW1 and the agreed GW2 architecture

| Agreed requirement | Present in GW1? | Gap |
|---|---|---|
| A. Declared requirements gate completeness | No. Coverage is reported (gaps.ts for evidence, audit.ts for citations) but never gates anything. | Policy record + completeness evaluator (P1). |
| A. Reliable page-access recording | No. Only Kane's own step remarks (follow-up reconstruction). | Server-side access log (P1). |
| A. Completeness separate from detection | Partly. `audit.ts` and the findings are separate files, but the QA report does not state completeness. | Separate completeness section (P1). |
| B. Blind Rule Discovery | No. GW1 was specification-guided: the index page lists R1–R15 and Kane's objective names them. | Blind view, hypothesis form, freeze (P3). |
| C. Three-way verification | No. GW1 compares observation with specification only, by the agent and the coding agent. | Verifier and three relations (P4). |
| D. Declarative hypotheses, deterministic verification | No. Findings are free text. | Representation + interpreter (P4). |
| E. Immutable branching judgments | Partly: findings are append-only NDJSON and labels are a separate post-freeze file, but there is no link structure, evaluator identity or challenge record. | Judgment graph (P2). |
| F. Separation and leak prevention | Partly: blind workspace for the repair agent, leak check on pages, private ground truth. The review site carries the specification and descriptive script titles by design. | Partitions + blind leak checks (P3). |

## 5. Existing defects found during Phase 0 (not repaired)

Listed here and in [`PHASE_0_REPORT.md`](PHASE_0_REPORT.md) §7. Phase 0 does not fix them.

1. **`tests/playtest-referee.test.ts`: 5 of 5 tests cancelled** in this environment (Node 22.23.5, Linux) with
   `Promise resolution is still pending but the event loop has already resolved`. Deterministic on re-run. Not a
   GameWatch file; last changed in `8b5b4bb` (2026-11-21). Earlier reports recorded passing suites on the operator's
   machine, so this may be environment-specific. Not investigated further.
2. **`gamewatch/kane/plan.ts` writes into frozen evidence**: every run rewrites `evidence/gamewatch/review/PLAN.json`
   (and `run.ts` dry run calls `plan.ts`). The content is currently identical, so `git status` stays clean, but a
   change to `plan-data.ts` would silently alter a frozen GW1 file.
3. **`gamewatch/dashboard.ts` deletes and rebuilds `evidence/gamewatch/site/`**. The SkillBook's `port-pages` task
   regenerates frozen pages in place. It was byte-identical in the Phase 0 run, but a dashboard change would alter
   frozen evidence. GW2 must point it at a new output directory.
4. **`audit.ts` matches case/match ids by substring and counts citation, not access**. A finding that cites an id it
   never opened counts as coverage (GW1 finding 1, C-9fc650).
5. **`gamewatch/kane/serve.test.ts` is not part of `npm test`** (the glob is `tests/*.test.ts`); it passes when run
   directly (2/2).
6. **The Kane run summary is not authoritative** (already documented in `docs/GW1_FINAL_REPORT.md` §3.3): the
   pipeline correctly reads forms, not `run_end.summary`.
