| Q1 | Should P1 bring `followup/gw1-visit-coverage` (`45959318`, `46ee7e6`) onto the GW2 branch unchanged? | It is the only GW1 visitation signal and is reused by P1 (AC-P1.5). It is not yet reviewed or in a PR. | Yes, merge as-is at the start of P1 with the operator's OK, then wrap, not edit. |
| Q2 | Is server-side access logging on by default? | Changes the behaviour of `serve.ts` for every user, though only by adding a file. | On by default, with a flag to disable. |
| Q3 | Who writes and who reviews the machine-readable encoding of the specification (R1–R15 as `gw2-hypothesis@1`)? | The encoding becomes the reference for H↔S and O↔S; an encoding error biases every result (T5). | Claude drafts in P4; the operator reviews each rule before it is used in P5/P7. |
| Q4 | After the specification reveal, is the agent asked to reconcile (a new inference call), or is reconciliation only the deterministic comparison? | An extra call per experiment; it also measures something different (revision quality, D12). | Deterministic comparison in P4–P6; agent reconciliation as an optional P7 arm. |
| Q5 | How are discovery and held-out observations split (seeds, scripts, match vs case, proportion)? | Determines what "held-out predictive accuracy" means and whether some rules are untestable in held-out. | Disjoint seeds for matches; disjoint script variants for cases; each rule exercised in both partitions; fixed in P3 before any evidence is generated. |
| Q6 | May P5 generate new situations by running the (unchanged) build engines, to separate competing hypotheses? | Increases discriminating power but adds a new evidence source after hypotheses exist (selection risk). | Yes, but only with a generator fixed before the freeze and recorded with provenance. |
| Q7 | Does the agent see verifier feedback during an investigation, or only after? | Feedback during the run is a strong intervention and confounds "architecture" with "being told the answer is wrong" (T11). | No feedback during discovery in the first P7 experiment. |
| Q8 | Number of real-agent calls, credits and models for P7. | Sample size determines whether any rate can be reported (T13). | Operator decision at P7 pre-registration. |
| Q9 | Where is P7 ground truth stored before publication? | `gamewatch/private/` is public in this repository (T1). | Outside the repository (operator machine or a private repo), hashed into the pre-registration. |
| Q10 | In blind mode, are effect names ("Shield", "Send home", "+1 action") observation or specification? | They are visible in the game's own events, but they hint at intended behaviour. | Keep them (they are what the engine reports); remove descriptive script titles and rule text. Revisit after P3 leak review. |
| Q11 | Should the pre-existing defects in CURRENT_ARCHITECTURE §5 be fixed, and in which phase? | Items 2 and 3 can alter frozen evidence by accident. | Guard items 2–3 in P1 (write to new paths); leave item 1 to a separate repair task. |
